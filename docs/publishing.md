# راهنمای انتشار ابزار جدید

این سند برای نگهدارنده سایت است، نه بازدیدکننده. کل چرخه انتشار سه قدم دارد و
هیچ فایل HTML ای لازم نیست ویرایش شود.

---

## چرخه انتشار در سه قدم

### ۱. پوشه محصول را بسازید

```
products/ea/my-tool/            ← اکسپرت
products/indicators/my-tool/    ← اندیکاتور
```

داخل پوشه، حداقل یک `product.json` بگذارید و فایل‌های واقعی را کنارش کپی کنید:

```
products/ea/my-tool/
├── product.json          الزامی — متادیتا
├── MyTool.ex5            فایل کامپایل‌شده (وقتی آماده انتشار است)
├── MyTool.mq5            کد منبع (اختیاری ولی مفید)
├── preview.png           تصویر چارت (اختیاری، نسبت ۱۶:۱۰ بهترین نتیجه را می‌دهد)
└── README.md             مستندات (اختیاری، در صفحه ابزار رندر می‌شود)
```

نمونه `product.json`:

```json
{
  "id": "my-tool",
  "type": "ea",
  "name": "My Tool",
  "version": "1.0",
  "author": "MT5 Tools",
  "symbol": "XAUUSD",
  "timeframe": "M15",
  "description": "یک یا دو جمله که در فهرست‌ها و نتایج جست‌وجو دیده می‌شود.",
  "free": true,
  "featured": true,
  "tags": ["gold", "trend", "طلا"],
  "features": ["حجم ثابت یا درصد ریسک", "فیلتر سشن"],
  "requirements": [],
  "updated": "2026-09-18",
  "license": "استفاده آزاد",
  "changelog": [
    { "version": "1.0", "date": "2026-09-18", "notes": ["اولین انتشار."] }
  ]
}
```

فیلد `symbol` را اگر ابزار به نماد خاصی وابسته نیست `"All"` بگذارید و اگر
نمی‌دانید، کلید را حذف کنید؛ در آن حالت سایت «تعیین نشده» نشان می‌دهد و ادعای
نادرست نمی‌کند.

### ۲. فایل واقعی را بگذارید و `file` را به آن وصل کنید

نام فایل در `product.json` (`"file": "MyTool.ex5"`) باید **دقیقاً** با نام فایل
روی دیسک یکی باشد. اگر فایل را نمی‌گذارید، کلید `file` را نگذارید: سایت صفحه
ابزار را با دکمه دانلود غیرفعال نشان می‌دهد و هیچ لینک شکسته‌ای ساخته نمی‌شود.

### ۳. بررسی، ساخت و پوش

```bash
python3 scripts/build_catalog.py --check --strict   # اعتبارسنجی، بدون نوشتن فایل
python3 scripts/build_catalog.py                    # ساخت catalog.json و sitemap.xml
python3 -m http.server 8080                          # پیش‌نمایش محلی: http://localhost:8080/
git add products/ assets/data/catalog.json sitemap.xml
git commit -m "feat: add My Tool"
git push origin main
```

وورک‌فلوی `.github/workflows/deploy.yml` بعد از هر پوش به `main`، خودش
اعتبارسنجی و ساخت کاتالوگ را انجام می‌دهد و سایت را منتشر می‌کند؛ بنابراین اجرای
محلی اسکریپت فقط برای پیش‌نمایش و برای اطمینان از سالم بودن داده است.

## انتشار نسخه جدید یک ابزار

۱. فایل قدیمی را با فایل جدید **جایگزین** کنید (یا کنارش بگذارید و `file` را
   به‌روز کنید).
۲. `version` را بالا ببرید.
۳. یک رکورد تازه در `changelog` اضافه کنید (`version`, `date`, `notes`).
۴. `updated` را روی تاریخ امروز بگذارید.
۵. پوش کنید. آدرس صفحه محصول (`product.html?id=my-tool`) هرگز تغییر نمی‌کند.

## چیزهایی که هرگز در مخزن نگذارید

- **فایل جایگزین یا placeholder.** اسکریپت هر فایل `.ex5/.mq5/.mqh/.zip/.set/`
  `.tpl/.chr/.pdf/.csv` را که در پوشه ببیند، به‌عنوان دانلود واقعی معرفی می‌کند.
  یک فایل متنی با نام `MyTool.ex5` به کاربر تحویل داده می‌شود.
- **تصویر نامعتبر با نام `preview.png`.** اگر تصویر واقعی ندارید، فایل را نگذارید؛
  سایت خودش کاشی «بدون پیش‌نمایش» می‌سازد.
- **مسیر مطلق از ریشه** (`/downloads/...`). سایت روی
  `https://USER.github.io/REPO/` سرو می‌شود؛ همه مسیرها باید نسبی باشند.
- **توکن، کلید API یا هر رمزی.** همه‌چیز این مخزن عمومی و منتشرشده است.

## عیب‌یابی سریع

| نشانه | علت | راه‌حل |
| --- | --- | --- |
| ابزار در سایت نیست | کاتالوگ قدیمی است | `python3 scripts/build_catalog.py` را اجرا و کامیت کنید |
| دکمه دانلود غیرفعال است | `file` نبوده، یا نامش با فایل روی دیسک یکی نیست | نام دقیق فایل را در `file` بگذارید |
| تصویر پیش‌نمایش دیده نمی‌شود | فایل تصویر نیست یا نامش `preview.png` نیست | تصویر واقعی را با همان نام اضافه کنید |
| جست‌وجو ابزار را پیدا نمی‌کند | فیلدهای `tags`/`symbol`/`timeframe` خالی است | متادیتا را کامل کنید |
| اجرای CI قرمز شده است | `--strict` یک هشدار داده | متن هشدار در لاگ Actions نام فایل مشکل‌دار را می‌گوید |
